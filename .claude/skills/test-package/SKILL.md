# Testing a built nixpkgs PR package

You produce **evidence, not verdicts**. The output is a transcript of what you
ran and what happened, for a human to read and judge. Someone else signs the
review with their name and is accountable for it upstream.

**Read `docs/verifying-findings.md` before writing down any finding.** It is the
kit's verification protocol: eight rules, each with the real case that produced
it. They are deliberately not restated here — a second copy would go stale, and
a summary would silently drop whichever rule was added last.

## Hard rules

- **Never post, comment, approve, or merge.** Not with `gh`, not through any
  other path. The kit pins `on-success=nothing` for the same reason.
- **Never write review-comment text.** No "LGTM", no filled-in
  `templates/review-comment.md`, no wording meant to be pasted into GitHub. A
  transcript that reads like a draft review invites posting something nobody
  read. If asked for a review comment, say the transcript is the input to one
  and stop.
- **Never claim a check you did not run.** No inferring `--version` output, no
  "should work". If a command failed, or you skipped it, that goes in the
  transcript verbatim.
- **Do not launch GUI applications.** See step 6.

## 1. Read what already exists

```bash
cat reports/N-notes.md      # the test plan: what changed, what to watch out for
cat reports/N-gha.md        # the Actions build report
cat reports/N-triage.txt    # if failures were triaged
```

`reports/N-notes.md` is generated by `scripts/notes.sh` and lists the specific
things this PR needs checked. Test those, not just `--version`. If the notes are
missing, generate them: `scripts/notes.sh N`. Read its "Not checked" line if it
has one — that marks what the tooling could not determine, which is not the same
as clean.

## 2. Build locally if needed

The Actions run proves the build but leaves no store paths on this machine.

```bash
scripts/local-review.sh N --no-shell --print-result
```

Minutes for a leaf package, much longer for anything large — run it in the
background and do other work. Results land in
`$NIXPKGS_REVIEW_CACHE/pr-N/results/<attr>-<system>`.

## 3. Resolve the store path before running

```bash
. scripts/lib.sh   # for $NIXPKGS_REVIEW_CACHE, which respects XDG_CACHE_HOME
BIN=$(readlink -f "$NIXPKGS_REVIEW_CACHE/pr-N/results/<attr>-x86_64-linux")/bin/<prog>
```

**This matters.** The results symlink lives under the cache directory, which the
sandbox below hides — running it through the symlink fails with exit 203.

## 4. Run it in a sandbox

These are freshly built binaries from upstream releases that may be hours old.
Running one unsandboxed gives it your home directory, SSH keys and `gh` token.
A tester is among the first machines in the world to execute a new release,
which is exactly the position you do not want to be in unprotected.

```bash
sandbox() { systemd-run --user --pipe --wait --quiet \
  -p PrivateNetwork=yes -p ProtectHome=yes -p PrivateTmp=yes "$@"; }

sandbox "$BIN" --version
```

- `PrivateNetwork=yes` breaks tools that need the network. If the real task
  needs it, drop that one flag, keep the others, and **say so in the
  transcript** — it is a decision the reader should see.
- Inputs must live outside `$HOME`: pass them on the command line, or bind-mount
  a directory read-only with `-p BindReadOnlyPaths=...`.
- If `systemd-run` is unavailable, `nix-shell -p bubblewrap` and use `bwrap`.
  If neither works, say so in the transcript rather than silently running
  unsandboxed.

## 5. What to actually test

In order:

1. **`--version` matches the PR's new version.** A real check, not a formality:
   it catches a build that picked up the wrong source. Some programs have no
   version flag — say so and verify another way (the store path, the pinned rev's
   commit date) rather than skipping silently.
2. **`--help` runs** without crashing.
3. **One real task.** This is the part that matters and the part no script can
   write for you. Work out what the program is *for* and do a small genuine
   instance of it: run a program in an interpreter, convert a file, query
   something, generate a project skeleton. Prefer a task whose correct output you
   can verify yourself.
4. **Whatever `notes.sh` flagged.** A missing runtime dependency is checked by
   exercising the feature that imports it, or `<interpreter> -c 'import NAME'` —
   the interpreter, not the package's entry point.
5. **`passthru.tests`** if the notes mention them: `nix-build -A <attr>.tests`.

## 6. Packages you must not test this way

- **GUI applications** (the notes say so; notes.sh owns the trigger list).
  Launching windows on someone's desktop unasked is rude, and "it opened" is
  not evidence the editor works. Record that it needs hands-on testing by a
  person and stop.
- **Libraries with no executable.** Test a dependent from the build report
  instead, or use the library the way its consumers do. If you cannot, say so.
- **Anything needing credentials, a vault, or a server.** Check it starts and
  fails cleanly on missing input; do not invent credentials.

## 7. Write the transcript

To `reports/N-testlog.md`:

```markdown
# #N <attr>: <old> -> <new> — test log

Tested on x86_64-linux, <date>, from a local build of the PR branch.
Sandbox: systemd-run --user, PrivateNetwork=yes ProtectHome=yes PrivateTmp=yes
Store path: /nix/store/...-<attr>-<new>

## Commands run

$ tpl --version
Trealla Prolog (c) Infradig 2020, v3.9.39
  -> matches the PR's 3.9.39

$ <real task>
<verbatim output>
  -> <what this shows, one line, no more than the output supports>

## Not checked

- <what you skipped and why: GUI, needs credentials, network disabled>

## For the reviewer

- <observations a person should look at, phrased as observations>

---

**These are candidates, not conclusions.** Reproduce any finding yourself before
it goes on a public PR under your name.
```

Verbatim output, exact commands. If something looked wrong, put it under "For
the reviewer" as an observation, not a conclusion — you are describing what you
saw, and the person reviewing decides what it means.
